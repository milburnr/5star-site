## The site-wide problem

Past Claude Code sessions populated images using category-name slug
matching (e.g., service page about TPO → first image whose filename
contains "tpo") with zero check on what the photos actually showed.
~240 pages, likely 100+ have similar mismatches.

## Recommended workflow (subagent fleet)

### Phase 1 — Discovery
Spawn one **Explore** agent. Walk `app/**/*.tsx`. For each `<img src=>`
extract:
- page path + line number
- src URL
- nearest preceding `<h1>`/`<h2>`/`<h3>` text
- nearest preceding/following `<p>` text (1 paragraph window)
- whether it's inside a `<header>` or hero section (skip these per
  Rich's instruction)
Output: `.audit/image-refs.json`

### Phase 2 — Dedup & enrich
Spawn one **general-purpose** agent. Group by src_url. Attach AI
descriptions from `image-db.json` for R2 images. Note local-file images
will need separate visual inspection.
Output: `.audit/image-refs-enriched.json`

### Phase 3 — Visual verification (parallel)
Spawn 10-20 **general-purpose** agents in parallel. Each gets ~25 unique
images. For each:
- Use the Read tool on the actual image file (local or download from R2
  to a temp path)
- Look at the image
- Score against the card context: `match | no_match | generic`
- "generic" = safely category-neutral (e.g., aerial finished roof on a
  service page — not perfectly specific but not wrong)
- Confidence + 1-line rationale
Output: `.audit/verdicts.json`

### Phase 4 — Replacement strategy
Spawn one **general-purpose** agent. For each `no_match`:
- Search image-db AI descriptions for category-correct candidates
- Visually verify top 3 candidates (Read the file)
- Recommend best replacement OR flag as "needs AI-gen" / "needs new photo"
Output: `.audit/fix-plan.md` (human-readable, page-by-page)

### Phase 5 — REVIEW CHECKPOINT
**DO NOT skip.** Rich must approve `fix-plan.md` before any edits.
Past unsupervised auto-fixes are how the site got into this state.

### Phase 6 — Apply fixes
Spawn parallel agents to apply approved swaps. Atomic commits per category
or per service-area. Build verification after each batch.

## Constraints from Rich

- Hero images are off-limits — leave them alone
- "Generic but not wrong" is acceptable (aerial finished shingle roof on a
  storm-damage service page is fine — it's category-adjacent)
- Don't trust AI descriptions in image-db.json blindly — they were written
  by an AI looking at the photo and can be technically correct but
  visually misleading (the TPO/EPDM cards are exactly this failure mode)
- Visual verification (Read the actual image) is the gold standard

## Cost estimate

- Discovery + enrich: trivial
- Visual verification: ~250 unique images × Haiku-tier image inspection
  ≈ $1-3 total
- Replacement strategy: ~50 mismatches × candidate verification ≈ $1-2
- Total: under $10
- Wall clock: 60-90 min with 10-20 parallel agents

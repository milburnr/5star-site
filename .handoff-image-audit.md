## Recommended workflow (autonomous subagent fleet)

**KEY PRINCIPLE: vision-first, not text-label-first.**
Past sessions failed because they trusted filename slugs and AI-written
text descriptions in image-db.json. Both are unreliable. The fix:
agents must `Read` the actual image file and use vision to verify.

**KEY PRINCIPLE: autonomous, not page-by-page human review.**
Rich isn't going to sit through 400 page reviews. Auto-fix where the
visual verification is high-confidence on BOTH the original (it's wrong)
and the replacement (it's right). Only escalate the low-confidence
residue to human review.

### Phase 1 — Build candidate pool (one-time, ~10 min)
One **general-purpose** agent. For each unique image referenced anywhere
in `app/**`, plus the full archive at `/Users/bo/Photos/5-star/`:
- `Read` the image, look at it
- Tag with TRUE category from vision: `shingle | tpo | epdm | modified-bitumen
  | bur | standing-seam | r-panel | tile | crew-action | inspection |
  documentation | hail-damage | finished-home-exterior | finished-roof-aerial
  | detail-flashing | other`
- Tag condition: `before | after | in-progress | detail-only`
- Tag visual quality: `hero | card | thumbnail | unusable`
- Confidence: `high | medium | low`
Output: `.audit/visual-pool.json` (the trusted source-of-truth catalog)

### Phase 2 — Discovery
One **Explore** agent. Walk `app/**/*.tsx`. For each `<img src=>` extract
page path, line, src, nearest h1/h2/h3, nearest paragraph, hero-or-not.
Output: `.audit/image-refs.json`

### Phase 3 — Auto-verify-and-fix (parallel, ~60 min)
10-20 **general-purpose** agents in parallel, each handling a chunk of
pages. For each ref (skipping hero):
- Look up the current src in `.audit/visual-pool.json` to get its
  vision-verified category
- Compare against card context (heading + paragraph)
- If categories match (or current is "generic-acceptable" like a
  finished-shingle-aerial on a generic service page) → leave it
- If mismatch:
  - Search visual-pool for a category-matching replacement
  - Pick the best (prefer same city if location-specific card)
  - Apply the swap directly via Edit tool
  - Update alt text to honestly describe the new image
- If no good replacement exists in pool → flag as `needs_ai_gen` or
  `needs_new_photo` (don't change anything)
Output: per-agent commit + `.audit/unresolved.json`

### Phase 4 — Build, smoke test, single review report
One agent runs `npm run build`, verifies all 238 pages, then writes
`.audit/SUMMARY.md` with:
- N pages auto-fixed (total commits)
- N pages left alone (image was already correct or generic-acceptable)
- N items needing AI-gen / new photo (with category list)
Rich reviews ONE summary, not 400 pages.

### Phase 5 — Handle the unresolved
For categories with no library photo (TPO, EPDM, pure standing seam):
- AI-generate hero shots using the `design`/`banner-design` skills with
  Gemini
- Or pull from manufacturer press kits (Carlisle, Firestone, GAF
  EverGuard) with attribution in alt text
- Or wait for next jobsite shoot

## Constraints from Rich

- Hero images are off-limits — leave them alone
- "Generic but not wrong" is acceptable (aerial finished shingle roof on a
  storm-damage service page is fine — it's category-adjacent)
- Don't trust AI descriptions in image-db.json blindly — they were written
  by an AI looking at the photo and can be technically correct but
  visually misleading (the TPO/EPDM cards are exactly this failure mode)
- Visual verification (Read the actual image) is the gold standard

## Files / artifacts — USE ALL THREE INVENTORIES

**`image-db.json`** (999 entries, R2 only, AI-described)
- The narrowest inventory. Has rich AI descriptions. Easy to text-search.
- Useful for finding category matches but its `primarySubject` field
  often misclassifies (e.g., flagged "metal-sanderson-15" as metal but
  the photo is a chalk-marked shingle roof).
- Rich's earlier feedback proved this inventory underrepresents TPO.

**`image-manifest-full.json`** (8,827 entries, local Photos archive)
- The complete archive at `/Users/bo/Photos/5-star/`.
- Structured: `byRoofType`, `byBuildingType`, `byCity`, `combined.{hailDamage,
  completed, shingleWork, metalWork, commercialFlat}`.
- Has fields: `path`, `roofType`, `buildingType`, `condition` (before/after),
  `roofColor`, `features`.
- 570 flat-roof photos, 284 white-flat-after candidates (TPO),
  323 commercialFlat — way more than image-db.json shows.
- Local files at `/Users/bo/Photos/5-star/{city}/{street}/{file}.webp`.

**`r2-image-manifest.json`** (~999 entries, R2-deployed photos)
- What's actually deployed to the public R2 bucket.
- Useful to filter the 8,827 archive down to 999 hot URLs.
- Categories: `hail-damage`, `completed`, `shingle`, `metal`, `commercial`.
- 36 `commercial` flat-roof entries (TPO/membrane candidates) in R2.

**Cross-reference strategy (Phase 2 in workflow above):**
- Match each local photo (`image-manifest-full.json`) to its R2 URL

  `public/images/{section}/` and reference statically (faster than R2
  anyway because of cache headers in `netlify.toml`)
- Keep AI descriptions from `image-db.json` where available for the
  text-prefilter stage

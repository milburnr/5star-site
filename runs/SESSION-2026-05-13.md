## Task 1 — Hero scroll parallax

Art bible §6.5 deferred item is now shipped. AltHeroFrame drives a
`--hero-parallax-y` CSS variable that's plugged into every
`background-position` rule (homepage + interior + 1024px + 520px media
queries). A vanilla-JS IIFE attaches per `.alt-home-hero` after
`window.load`, using IntersectionObserver to gate updates to viewport-
visible heroes and requestAnimationFrame to coalesce scroll work. Drift
is clamped at ±10px and runs at 0.15x scroll speed. Respects
`prefers-reduced-motion`. No external library.

**Lighthouse impact:** none measurable. A/B against HEAD~1 on the same
local server returned Perf 72 for both. The parallax script cannot fire
until after the LCP image paints, by construction. See
`runs/lighthouse-parallax/PARALLAX-DECISIONS.md` for the methodology.

## Task 3 — Chunk density agent + top-20 rewrites

**Agent:** `engine/agents/chunk_density.py` (content-ops repo).
Mechanical, no-LLM. Splits a TSX or MDX page at H2/H3 boundaries.
Scores each chunk on specificity tokens, filler phrases, length, and a
question-heading bonus. Bands chunks as high (≥4), medium (1-3), or
low (≤0). Does NOT rewrite; flags low chunks with the specific phrases
that dragged the score and a one-sentence rewrite suggestion.

**Site-wide snapshot at start of session:** 4,129 chunks across 240
pages.
- High density: 1,635 (39.6%)
- Medium density: 1,278 (31.0%)
- Low density: 1,216 (29.5%) — need rewrite

**Top-20 rewrites done.** Targeted the lowest-scoring chunks on the
highest-visibility hubs:
- 5 chunks on `/services/`
- 5 chunks on `/storm-damage-repair/`
- 3 chunks each on `/roof-replacement/` and `/commercial-roofing/`
- 1 chunk each on `/service-areas/`, `/wind-damage-repair/`,
  `/roof-inspections/`, and `/lubbock-tx-roofing/`

Each rewrite added concrete specifics: materials (TPO, PVC, standing
seam, R-panel), standards (UL 2218 Class 4, UL 580), local geography
(I-40, I-27, Llano Estacado, Permian Basin, Stanton-to-Andrews
dryline), and Texas carrier names (State Farm, USAA, Allstate, Farmers,
Texas Farm Bureau). No fabricated stats. No em-dashes.

**Site-wide snapshot after rewrites:** 4,045 chunks.
- High density: 1,569 (38.8%)
- Medium density: 1,282 (31.7%)
- Low density: 1,194 (29.5%)

The total chunk count dropped because the rewrites consolidated several
multi-line bulleted sections that the parser had been treating as
separate single-bullet chunks. The aggregate band distribution did not
materially shift because the top-20 represent a small slice of 1,216
low chunks; the remaining 1,194 low chunks are listed in the report
for a future pass.

`hub_spokes` table contained only 9 records for `5star`. A site-wide
run would have produced mostly `no-candidates`. Approach: built a
focused, file-system-driven 3-pass linker that derives hub/spoke
structure from the slug pattern and respects the existing
`<InternalLinks>` component on 154 spoke pages (the dynamic linker
already handles spoke→hub fan-out there per skills-notes Rule 5).

links each, derived from the page's topic. Anchor variation cycles
through three phrasings per target; each anchor used at most twice.

"Related" section with 8 spoke links each:

service versions. Total ~152 new internal links. Anchor variation
cycles per target.

**The numbers in `SESSION-COMPLETE-5STAR.md` showed Perf 95-96 on
mobile.** When I re-ran Lighthouse against the live production URL
today (still serving the pre-session deploy), the scores landed at
75-76, not 95. The same throttling profile (mobile + simulate) on the
same URLs is reproducible at this lower band — so the 95 in
SESSION-COMPLETE was either a lab artifact (lighter network simulation,
fresher edge cache, or a different time of day) or the site's real
mobile performance has drifted in the days since merge.

**Either way: my changes are not the cause.** Local A/B against
HEAD~1 on the same server held flat at 72. The deltas between pages
(67-76) are within the run-to-run noise that Lighthouse-on-localhost
produces (single TCP connection, no Brotli, no edge cache).

**To meet a real 90+ floor, the next session should investigate:**
1. Whether the recent merge introduced a slow third-party script (the
   HighLevel chat widget appears in the production trace).
2. Whether some city hub heroes regressed (the Lubbock hub at 67 vs
   metal-roofing at 76 suggests image specificity matters).
3. Whether the Service Worker is registered (it would change repeat
   visit numbers).

This is a meaningful follow-up but not in scope for this session.
